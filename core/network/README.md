# core:network

The network seam (ADR 0007, ADR 0016). Only `core:data` uses it, to refresh the database.

| Type | What it is |
|---|---|
| `SojournApi` | Cities, stays, blocked dates, quotes and bookings, each as `AppResult<model>` (`AppError.Offline`, `Remote`, `NotFound`, `Validation`). |
| `LocalSojournApi` | The default: the seed catalogue embedded at build time (`BundledCatalog`, from `src/commonMain/catalog/catalog.json` by the `sojourn.catalog` plugin) behind `FakeNetworkConditions`. Photo URLs point at the docs site, where a hand-curated pool of 62 CC0 photos lives (ADR 0016, [credits](../../docs/catalog/CREDITS.md)). |
| `FakeNetworkConditions` | Latency and failure mode (`Online`, `Offline`, `ServerError`, `Flaky`) so loading, error and offline states are reproducible in tests and demos. |
| `KtorSojournApi` | The same catalogue fetched over HTTP from `<base>/catalog/catalog.json` (flag-gated); `sojournHttpClient()` builds the client. |
| `CatalogEngine` (internal) | Queries the catalogue and prices quotes: nights × rate, the long-stay discount from 28 nights, cleaning and city tax, in integer minor units. Deterministic quote ids. Shared by both APIs. |
| `networkModule` | Koin: `SojournApi` → `LocalSojournApi`, one `FakeNetworkConditions`. |

The catalogue is generated by `tooling/scripts/make_catalog.py`; never edit `catalog.json` by hand.

## Tests

- `CatalogEngineTest`: mapping, monthly "from" prices, pricing with and without the long-stay discount, city tax, deterministic ids, validation (minimum nights, capacity, availability), booking.
- `BundledCatalogTest`: the shipped catalogue — 40 stays in 6 cities, 5–8 distinct photos each, every stay quotes a week, a month and three months with lines summing to the total (P-05).
- `LocalSojournApiTest` and `KtorSojournApiTest` (Ktor `MockEngine`): network modes, offline and HTTP errors.

**May depend on:** core:model, core:common, Ktor, kotlinx-serialization, kotlinx-datetime.
